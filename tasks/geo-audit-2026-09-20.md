## 0. Executive summary

The pipeline is **alive and healthy as infrastructure** and **dead as a trading tool**.

| Prod fact (7 days) | Value |
|---|---|
| Cron cycles run / ok | 1008 / 1008, 336/336 HTTP 200, 0 missed slots |
| Cycle latency | median 128 s, max 230 s (deadline 1800 s) |
| Notifications sent, ever | **0** (1700 signals since 2026-06-18) |
| Max importance ever recorded | **57** (notify gate is ≥ 60) |
| Rules that have ever fired | **22 of 94** |
| Signals from FIRMS fires | **78 %** (1181 / 1700) |
| Sources dead in prod | `acled` 0/1010 runs, `flights` 0/1010, `gdelt` 168/1010 (16 %) |
| Checkpoint accuracy (ex-neutral) | **23.9 %** (1h: 9.7 % → 7d: 42.6 %); 4374 of 7810 scored exactly 0 |

Five root causes explain all five complaints:

1. **The notify gate is arithmetically unreachable.** `risk_score` is derived from
   confidence (`analyst.py:159`), so `importance = conf × risk/10` ≈ conf²/150. With the
   catalogue's max `base_confidence` 0.90, the ceiling is 54 (57 with learned mods). The LLM
   is gated on the same number, so it has never run either. → *"alerts not reaching channels"*.
2. **The news/policy channel does not exist in practice.** GDELT hardcodes 5 mentions per
   article but the sentinel floors are 8–15 → zero events even when GDELT answers (and it
   429s 83 % of the time). ACLED keys are unset. OpenSky OAuth fails 671×/7d → anonymous →
   nothing. Only 3 of 94 rules are economic/policy and all 3 are GDELT-only.
   → *"disconnected from events moving markets"*.
3. **The auditor measures "now" against T0, not the bar at T+Δ, with no market-hours
   awareness**, then burns the window as NEUTRAL forever on any Yahoo stall. Random baskets
   score ~61–68 % CORRECT under this scorer; the real 24 % is below coin-flip because most
   history was scored on stale closes. → *"checkpoints failing"*.
4. **No exposure model.** 61 of 94 rules have a basket where every leg is a globally
   diversified instrument; 16 tickers carry 72 % of all rule→ticker edges (GLD 32 rules, USO 30,
   LMT 23). Magnitude never touches confidence: M5.5 and M8.5 produce identical rows.
   → *"strong rain → worldwide ticker"*.
5. **63 tickers, 38 % US ETFs not buyable as cash by EU retail (61 % of edges)**, 4 symbols
   don't price at all (`NI=F`, `LBS=F`, `X`, `SSNLF`). → *"limited tickers to speculate"*.

`orchestrator.py:157` requires a rule match with tickers before the LLM runs, and
`orchestrator.py:178` drops any event without tickers. The LLM only *adds* tickers
(`analyst.py:153`), never removes or re-weights. A hand-written rule is the only way any
event becomes a signal.

## 2. Alert delivery & latency

### 2.1 Gate math (the blocker)
```
risk_score  = min(round(conf/15), 10)        # analyst.py:159-162, when no LLM
importance  = round(conf × risk_score/10)    # advisor.py:55
```
conf 90 → risk 6 → 54. conf 97.5 → 58. conf 98 → risk 7 → 69. There is a dead band 58–67.
Max base_confidence 0.90; multi-rule matches *average* (only pull down). 0 of 94 rules can
reach 60 on first sighting. 17 rules cannot reach 60 even at the +0.30 `confidence_mod`
ceiling. `orchestrator.py:154-160` gates the LLM on this same estimate → LLM dead → the only
independent `riskScore` source is unreachable. Prod: 1700 signals, max 57, 0 notified.

The notify test `test_geo_notify_cron.py:36-38` hand-builds `importance=72, confidence=0.8,
risk_score=9` — a state the pipeline cannot produce. It passes against fiction.

### 2.2 Silent paths in notify
- All three channel senders return `bool`; `notify.py:37-52` discards all three.
- Unconfigured topic/token/email → `return False` with **no log line**
  (`notification_service.py:31, 58, 91`).
- One `try` wraps ntfy → Telegram → email: a Telegram exception silently drops email;
  partial fan-out with no record.
- `smtplib.SMTP("smtp.gmail.com", 587)` has **no timeout** → can hold the synchronous cron
  request until the 1800 s deadline.
- No retry on 429/5xx/timeout (Telegram retries only on 400 to strip parse_mode).
- **No delivery record**: no `notified_at`, no `geo_notification` table.
  `GeoCycleRun.notified` counts attempts (incremented unconditionally), and
  `geoHealth.ts:19` declares the field but never renders it.
- Credentials are **global env vars**; `cron_run` iterates all users (3 in prod) and pushes
  every user's signals to the one configured phone/chat/mailbox. Blocks any SaaS path.

### 2.3 Latency budget (once the gate is fixed)
| Hop | Contribution |
|---|---|
| Feed lag | USGS ~2–15 min · GDACS tens of min · EONET hours–days · FIRMS ~3 h + 12 h revisit · ACLED days · GDELT re-reads a 24 h digest of 25 records with no `sort` |
| Cron `*/30` | mean 15 min |
| Cold start (`--min=0`) | 5–20 s; every `TTLCache` is process-local so prod never hits cache across cycles |
| Ingest | measured 59 s, **44 s is GDELT serial sleeps** |
| Prices + auditor | 2–6 s healthy, ≤150 s degraded (shared budget since PR #260) |
| Notify | 1–5 s, unbounded worst case (SMTP) |

Best case ≈ 3–4 min (USGS). Typical ≈ **22–28 min**. FIRMS/ACLED-sourced: hours to days,
cron cadence irrelevant. `*/10` previously cost ~259k vCPU-s/mo vs 240k free tier
(`docs/deployment.md:129`).

## 3. Checkpoints

### 3.1 Algorithm as implemented (`auditor.py`)
- T0 persisted per ticker at creation (`advisor.py:132-141`) — fine.
- T+Δ: **one** `fetch_ticker_prices` snapshot per cycle (`auditor.py:136`), = last 5-min bar
  "now", applied to **every due checkpoint of every signal**. Not the bar at `target_at`.
- Per-ticker: `|Δ| ≤ 0.1 %` excluded; score = correct/total; **score ≥ 50 → CORRECT (ties
  pass)**; total 0 → NEUTRAL. No magnitude, no benchmark, no weighting.
- No market-hours awareness anywhere. US RTH = 19 % of the week; ~80 % of signals are born
  on a stale close. Weekend 1h checkpoint compares Friday's bar with itself → NEUTRAL.
- Several horizons due in one cycle receive the identical price → 5 dots, 1 measurement.
- Yahoo stall / budget spent → `score None` → **NEUTRAL and `evaluated_at` stamped** →
  never retried. A single bad tick burns the window forever.

### 3.2 Measured noise vs threshold
Median |move| on the 10 most common basket symbols: 1h 0.24 %, 6h 0.98 %, 1d 1.04 %.
The flat 0.1 % dead-zone excludes ~nothing in-hours (27 % at 1h, 7 % at 1d).
Monte-Carlo, real 94 baskets, random in-hours timestamps, zero thesis:
**CORRECT 61–68 %** at every horizon. The scorer is biased toward passing and has no
discriminating power. 45 of 94 baskets are mixed long/short on one common factor → a
levered coin flip on the day's market direction.

### 3.3 Prod outcome matrix (8500 rows)
| horizon | CORRECT | INCORRECT | NEUTRAL | PENDING |
|---|---|---|---|---|
| 1h | 115 | 1076 | 509 | 0 |
| 6h | 173 | 1049 | 445 | 33 |
| 1d | 290 | 1129 | 230 | 51 |
| 3d | 439 | 1010 | 41 | 210 |

4374 evaluated rows scored exactly 0 (pre-fix history: close-vs-close = 0.00 % = fail).
The Sep-6 fixes stopped the bleeding going forward but did not repair history, and the board
fetches `status="all"`, so the old red rows stay visible.

### 3.4 Learning loop
`geo_rule_stats`: 76 rules at `confidence_mod = 0` (never fired), 2 at the −0.30 floor
(`fire-canada-lumber` 0 % over 102 signals — plausibly an artifact of `LBS=F` never pricing;
`vol-indonesia-palm`), 3 at +0.30. No endpoint exposes or resets the table; `seed_rule_stats`
never overwrites. The loop is unobservable and unresettable, and it has been fed by a
scorer that measures noise.

### 3.5 UI
NEUTRAL amber `#9A6B1F` vs INCORRECT red `#9B3D2C` at 3.5 px dots is not a distinction a
human makes. No accuracy aggregate exists anywhere. `c.outcome ?? "NEUTRAL"` at
`SignalPanel.tsx:464` paints evaluated-but-null as amber (latent lie).

The three commodity-basin rules added in #177 (`cyc-australia-ironore`,
`drought-westafrica-cocoa`, `eq-lithium-triangle`) are the template: narrow box, specific
price, explicit mechanism. The other 91 are not written that way.

### 4.3 Structural gaps
- **No exposure/materiality model.** `FastRule` has no scope, weight or exposure field.
  Baskets are static per rule; when two matched rules disagree on a symbol, `analyst.py:56`
  first-writer-wins by `FAST_RULES` order, unlogged.
- **Magnitude is a gate only.** `magnitude` is read once (`rules.py:277-281`); confidence,
  risk and importance are pure functions of `base_confidence`. M6.0 and M8.5 → identical row.
  Same for GDACS orange vs red, fire cluster 30 vs 3000, 46 °C vs 52 °C.
- Auditor weights every leg equally, so learned `confidence_mod` is dominated by GLD/USO
  drift, not the thesis.
- `.info` `country`/`sector` could feed a *negative* gate but `geo.md:145` forbids
  fundamentals as a gate input; the exposure table belongs in `rules.py` as static data.

### 4.4 Tradability (TR / DEGIRO / IBKR / ING / eToro)
US ETFs are reachable via **options at IBKR** (the desk already links `/options?ticker=`),
which covers GLD, USO, XLE, SOXX, FXI, EWZ, EWJ, URA, GDX, LIT — but JETS, BDRY, SOYB, WEAT,
XRT, REMX, TUR, COPX have negligible chains. The UI shows no distinction. UCITS families
exist for most (SGLN/4GLD, CRUD/BRNT, NGAS, SXLE, SMH, DFNS, iShares country range, U3O8);
JETS/BDRY/XRT have none → use IAG.MC / GOGL.OL / ITX.MC. Exact tickers need verifying
against current broker lists before coding.

## 5. Recommended plan (smallest shippable slices first)

### Phase 0 — unblock (all S, one PR each, ~1 week)
1. **Decouple `risk_score` from confidence** — explicit `risk` per `FastRule` (or from
   severity/chokepoint criticality), LLM may override. Break the `use_llm ⇐ est_importance`
   circularity. **Test: at least one rule yields `should_notify=True` from a synthetic event
   with `confidence_mod=0`.** Rewrite the fictional notify fixture.
2. **Unblock GDELT**: drop the mention/source floors (unsatisfiable), word-boundary
   classifier, run the 3 queries concurrently (−44 s/cycle), `sort=DateDesc`, shorter
   `timespan`. Test: ≥1 event survives a realistic fixture.
3. **Revive dead sources**: set `FINVIEW_ACLED_EMAIL/KEY` on Cloud Run; add `order` param to
   the ACLED query; diagnose the OpenSky token exchange (671 failures/7d — likely credential
   or endpoint change, needs a log line with the HTTP status).
4. **Notify observability**: per-channel return values kept, `logger.warning` on the three
   unconfigured branches, separate `try` per channel, `timeout=15` on SMTP, one retry on
   429/5xx, `notified_at` on `GeoSignal` (via `_ADDITIVE_COLUMNS`) and render
   `notified` in the health line.
5. **Dead tickers**: `LBS=F`→`LB=F`, drop `NI=F`/`X`, `SSNLF`→`005930.KS`. Offline test
   freezing the ticker universe so new symbols cannot enter unclassified.

### Phase 1 — make checkpoints mean something (M)
6. Market-hours-aware horizons (define in trading time; push `target_at` forward when the
   window has no session).
7. Price the bar at `target_at` (historical intraday), one dict per checkpoint; **do not stamp
   `evaluated_at` when nothing resolved** so a stall retries instead of burning.
8. Min-move threshold scaled to realised volatility per ticker (≈0.75 σ_horizon); benchmark-
   relative, magnitude-weighted signed score with a margin instead of `≥ 50` ties-pass.
9. `GET /geo/accuracy` (per-horizon matrix, per-rule mod/accuracy) + a reset path for
   `geo_rule_stats`; consider archiving pre-Sep-6 checkpoint rows from the accuracy read.

### Phase 2 — scoping (S code / M content)
10. `chain: (physical effect, price/flow, instrument)` replacing free-text `direction`
    (derived property → zero API/UI change). Rules with no writable chain get dropped.
11. `scope` per rule + `INSTRUMENT_BREADTH` per ticker; invariant `scope ≥ breadth` enforced
    by a test with a shrinking `KNOWN_VIOLATIONS` set; confidence penalty on the worst mismatch
    in `effective_confidence()`.
12. Severity scaling: magnitude/severity/cluster headroom over the rule threshold feeds
    confidence (test: M8.5 outranks M6.0).
13. Tradability tag per ticker (cash-EU / options-only / not-tradable) + UCITS alternate,
    rendered on the chip.

### Phase 3 — see the market (M/L)
14. Wire `macro_context.py` (FRED already keyed) into the geo cycle as a regime multiplier
    and as an event source (surprise vs consensus).
15. Keyless policy ingest: Federal Register API (tariffs, export controls), OFAC SDN changes,
    a central-bank/data-release calendar.
16. Generative LLM path for high-salience unmatched events (real headline text, proposes
    tickers + confidence, tagged `llm_generated`, audited separately so it can't poison
    `geo_rule_stats`).
17. Only after 1–4: a second narrow cron (`*/10`, USGS + GDACS + OpenSky only, no prices, no
    auditor) for the fast sources; keep `*/30` for the full cycle.

### Explicitly not recommended
- Shortening `*/30` before Phase 0: the gate is closed, so faster cycles deliver nothing
  faster; feed lag dominates for FIRMS/ACLED anyway.
- Enabling more physical-event sources/keys first: physical events are already 49 % of rules
  and 78 % of prod signals.
